## Make targets

| Target | Does |
|----|----|
| `make all` | build, docs, LaTeX, pkgdown, quarto, coverage |
| `make lint` | style and lint the R code, and report Overleaf limits |
| `make sizecheck` | check Overleaf limits; run before uploading |
| `make spec TOPIC=<topic>` | start a spec for a change set |
| `make log TOPIC=<topic> SUMMARY="..."` | write the change-set log and its file list (`UPDATE=TRUE` refreshes the list) |
| `make verify RECORD=TRUE` | after the user pushes from Overleaf (O2G): verify and record the push. On Roar, run `bash .setup/scripts/verify.sh` on the host first to pull. |
| `make auto` | publish to the public repository (checks the export first) |
| `make tree` | the project’s folders and what each is for; flags missing and non-standard folders |
| `make project` | settings, template files; restores `.setup/scripts/rproject.lock` (rProject, image, snapshot) |
| `make upgrade` | move to the newest rProject; the next `make auto` updates the lock. Never upgrade a package the image has: add it to the image |

## Size

Overleaf’s GitHub sync stops above 7 MB of editable text and caps text
files at 2 MB. Keep large data compressed (binary, e.g. `.Rds` or `.xz`)
and never store the same file twice. `make sizecheck` reports problems.

## Package

- Every exported function has roxygen documentation and tests.
- `make all` runs the checks; fix every error, warning, and note.
- Keep the R style rules from your global instructions (BigCamelCase,
  one function per file, internal `.Foo` functions in
  `R/<pkg>-<name>-dot.R`).

## CRAN

This package is on CRAN or headed there.

- `R CMD check --as-cran` must pass with no errors, warnings, or notes,
  on R release and R devel.
- Every user-visible change: a version bump and a `NEWS.md` entry.
- Examples, tests, and vignettes write only to
  [`tempdir()`](https://rdrr.io/r/base/tempfile.html), use at most two
  cores, and do not need the internet unless skipped (`skip_on_cran()`,
  `skip_if_offline()`). Long examples go in `\donttest{}`.
- Before a submission: `cran-comments.md` (test environments, check
  results, reverse dependencies) and reverse-dependency checks when the
  package has any.
- The user submits to CRAN. Agents prepare the submission; they never
  submit.
